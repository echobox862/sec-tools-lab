## 三、五个工具统一的技术约定

| 约定 | 决定 | 理由 |
|---|---|---|
| Python 版本 | 3.10+ | 实训材料含 Python 2 痕迹（urllib2/optparse），统一到现代写法 |
| CLI 解析 | `argparse`（不用 optparse） | optparse 已废弃；argparse 是「脚本→工具」的标志 |
| 并发 | `threading` + `Semaphore` 控制并发数 | 五个任务全是 I/O 密集（等网络响应），GIL 下多线程有效；**不引入 asyncio**（学习曲线陡，MVP 收益低） |
| 超时 | 一切网络操作必须显式 `settimeout()`，默认 1.0s 可配置 | 实训教训：无超时 = 扫描卡死 |
| 结果输出 | 统一支持 CSV / JSON 两种导出 | 便于截图展示与复用 |
| 启动横幅 | 打印「仅用于授权测试环境与学习」 | GitHub 展示的合规底线 |
| 判定纪律 | 所有验证类动作只读、不破坏（POC 原则） | 实训材料明确要求，也是职业底线 |

## 四、MVP 总表（必须实现 vs 暂时不做）

| 工具 | 必须实现（P0） | 应实现（P1） | 暂时不做（P2） | 核心取舍理由 |
|---|---|---|---|---|
| 01 端口扫描器 | socket `connect_ex` 全连接扫描 + 短超时 + 多线程 + CSV 导出 | python-nmap 后端（可选 `--engine nmap`） | SYN/XMAS/UDP 原始套接字扫描、IPv6、asyncio | 原始套接字需管理员权限 + 手工构包 + 跨平台行为不一致；全连接扫描已完整覆盖「原理→造轮子」学习目标 |
| 02 字典生成器 | 模板规则引擎（基础词×连接符×年份×数字）+ 生成器流式输出 + 总量预估防爆 | exrex 正则引擎后端（可选） | 正则解析器自研、GUI、社工库 | `exrex.generate` 思路照搬即可，MVP 用 itertools 笛卡尔积实现同样效果；总量预估是防爆保护，必做 |
| 03 SSH 爆破 | paramiko 单次尝试封装 + 每次尝试新建连接 + 参数化 CLI + 字典加载 + 1000 次上限 | 多线程（≤5）+ `detect_auth_methods` 预检 | 密钥认证爆破、私钥泄露扫描、分布式 | 「每次新建连接」是对 `MaxAuthTries` 的正确应对（材料未提但必做）；密钥认证不可爆破（质询-应答无密可猜），做了没有意义 |
| 04 Web 登录爆破 | 自适应表单解析（`find_all('input')`）+ csrf_token 自动携带 + 判定信号可配置 + 单线程 | 多线程（≤5）+ 每次尝试前刷新 token | 验证码识别、代理池、分布式、Headless 浏览器 | 自适应表单是本工具的灵魂（不写死字段名）；验证码是另一量级的问题，遇到即退出并提示 |
| 05 tamper | `double_keywords`（关键字双写）+ `case_mangle`（大小写混写）+ 独立验证脚本 verify.py | `comment_inline`（内联注释） | 编码类绕过、空格绕过、Header 类 tamper | 双写是实训主线且可本地验证；编码类绕过对目标数据库依赖强、验证成本高，学习收益低于前两个 |

**跨工具依赖顺序（开发顺序）**：01 → 02 →（03 ∥ 04）→ 05。01 和 02 无依赖先行；03 消费 01 的输出（开放 22 端口主机）与 02 的字典；04 消费 02 的字典；05 独立收尾（需要 sqlmap 环境，验证依赖本地 sqli-labs）。
