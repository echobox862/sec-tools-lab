## 1. 核心业务对象与关键属性

### ScanTarget（扫描目标）

| 属性 | 类型 | 说明 | 校验规则 |
|---|---|---|---|
| `host` | str | IP 或域名 | 先判断是否合法 IPv4；否则按域名解析，解析失败报错退出 |
| `ports` | list[int] | 待扫描端口列表 | 展开范围语法（如 `1-1024`、`22,80,443`）；每个值必须在 1–65535 |
| `timeout` | float | 单次连接超时秒数 | 默认 1.0；范围 0.1–10.0；**必须有**（实训教训：默认超时几十秒，扫描会卡死） |

### PortResult（单端口结果）

| 属性 | 类型 | 说明 |
|---|---|---|
| `port` | int | 端口号 |
| `status` | enum | `open`（connect_ex 返回 0）/ `closed` / `filtered`（超时，无法区分开放还是被防火墙丢弃——**输出为 filtered 而不是 closed，这是关键的正确性问题**） |
| `elapsed_ms` | float | 该次尝试耗时（用于调优超时参数） |

### ScanReport（扫描报告）

| 属性 | 类型 | 说明 |
|---|---|---|
| `target` | str | 目标标识 |
| `started_at / finished_at` | datetime | 起止时间 |
| `results` | list[PortResult] | 结果列表 |
| `summary` | dict | `{open: n, closed: n, filtered: n, total: n, elapsed_s: x}` |

## 3. 实现步骤与模块依赖顺序

```
第1步 parse_ports      （无依赖：纯字符串解析，先做，可单独测试）
第2步 scan_port        （依赖1：单端口核心，用 127.0.0.1 自测）
第3步 scan_host        （依赖2：包一层线程池；Semaphore 控制）
第4步 export_csv/json  （依赖2的数据结构：与3并行开发）
第5步 CLI argparse     （串起 1-4）
第6步(P1) nmap 后端    （独立，可选）
```

两个必须遵守的实现要点（来自实训材料）：
1. **用 `connect_ex()` 不用 `connect()`**——把异常控制流变成返回码判断（0=开放），批量场景更稳。
2. **多线程有效的前提是 I/O 密集**——等待网络响应时 GIL 释放；这是选 threading 不选 multiprocessing 的依据。

## 4. 边界条件与异常场景

| # | 场景 | 触发条件 | 预期行为 |
|---|---|---|---|
| 1 | 非法端口值 | `0`、`65536`、`abc` | ValueError，提示合法范围，退出码 2 |
| 2 | 起止倒置 | `1000-100` | ValueError，提示范围顺序错误 |
| 3 | 域名解析失败 | host 不存在 | 明确报错「DNS 解析失败」，退出码 3 |
| 4 | 目标不可达 | 网络不通 / 主机关机 | 全部结果为 filtered（等待超时），summary 提示「未收到任何响应，结果可信度低」 |
| 5 | 全部关闭 | 所有端口 closed | 正常输出空 open 列表 + 统计，**不是错误** |
| 6 | 防火墙 DROP | filtered 大量出现 | summary 中标注 filtered 占比，提醒「结果含不确定项」 |
| 7 | 超时设置过短 | timeout=0.05 且跨公网 | 大量误判 filtered；启动时若 timeout<0.3 打印警告 |
| 8 | 线程过多 | threads > 1000 | 句柄/fd 耗尽风险；上限硬编码 1000，默认 200 |
| 9 | 扫描 localhost | host=127.0.0.1 | 正常（学习主场景） |
| 10 | KeyboardInterrupt | Ctrl+C | 捕获后输出已完成的 partial report 再退出，不静默 |
| 11 | nmap 后端缺依赖 | 系统 nmap 未装 | P1 阶段处理：检测 shutil.which('nmap')，缺失则提示改用 socket 引擎 |
| 12 | IPv6 输入 | `::1` | P0 明确不支持，报错提示 |

## 5. MVP 划分

**必须实现（P0）**：parse_ports / scan_port / scan_host（socket 引擎）/ CSV 导出 / argparse CLI / 超时与并发上限 / 启动合规横幅。

**暂时不做（P2）**：
- SYN 半开、XMAS、FIN/NULL、UDP、僵尸扫描——需要原始套接字（root/管理员）+ 手工构造 TCP 包 + 各 OS 对畸形包响应不一致（材料明确「对 Windows 目标不可靠」）；**学习收益已被「理解原理」覆盖，实现成本与误用风险高**。
- IPv6、asyncio、服务版本识别（-sV 等价物）、主机发现（ping 扫）。

**P1（有余力再做）**：python-nmap 后端——价值在对照学习（`command_line()` 能打印出实际执行的 nmap 命令），作为「封装透明化」的教学点展示。

## 6. 验收标准

- 对 `127.0.0.1` 跑 `1-1024`：能正确识别本机实际监听端口为 open。
- 对一个明确关闭的端口：closed；对一个不响应的公网 IP：filtered。
- `-h` 输出完整参数说明；非法输入全部有明确报错。
- CSV 能被 Excel 正常打开（UTF-8 BOM 或纯 ASCII 字段）。
